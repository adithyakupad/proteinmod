# M14: learned edge-aware structural encoding

M14 annotates the validated M2 graph without changing its residue mapping or contact
and backbone topology. `edge_chemistry.py` reparses the checksum-pinned coordinates
with the existing alternate-conformer and reference alignment rules and verifies
all node author IDs, insertion codes, polymer positions and residue identities.
`edge_gnn.py` consumes graphs; it does not parse files or construct graph edges.
Existing M3–M13 model APIs, ESM caches and bidirectional cross-attention are unchanged.

The [prespecified plan](m14_plan.md) was committed at `087712c` before any fitting.
All nine models use the same original M12 G1/G2/G3 and M6 S1/S2 roles, without M13's
calibration-role substitutions. Primary targets remain assay-specific empirical
training percentiles; native targets remain experimental ΔΔG_fold kcal/mol,
**positive destabilizing**. Separate fits are made for the two cohorts. M14 does
not transfer supervised checkpoints, pool physical and DMS labels or fit multitask
heads. The primary cohort itself measures stability mutation effects, not new
functional endpoints.

## Graph inputs and controls

Nodes retain M3's 34 reference identity/biochemistry/geometry/missingness features
plus 25 mutation indicators/substituted identity/property deltas. Mutations are
validated/canonicalized by the existing mutation-set parser. Multiple mutations
are represented jointly; readout concatenates their sum, mean, global residue mean
and mutation count. This is invariant to mutation input order and node relabeling.
Reference geometry does not represent experimentally observed mutant rearrangements.

Each existing directed edge receives 29 features: 16 fixed distance radial bases
(centers 0–12 Å, width 0.8 Å), the original distance/8, spatial and backbone flags,
three chemical candidates, three corresponding validity masks and four symmetric
residue-category pairs. Spatial contacts retain M2's 8 Å Cα cutoff; backbone flags
retain M2's sequential polymer and validated peptide C–N geometry checks. Chemistry
annotates existing edges only; it is not a complete all-heavy-atom interaction network.

Salt-bridge candidates use observed Lys NZ / Arg NE,NH1,NH2 against Asp OD1,OD2 /
Glu OE1,OE2 at ≤4 Å; hydrophobic candidates use all declared sidechain carbon atoms
of A/V/I/L/M/F/W at ≤4.5 Å. A missing required atom masks that interaction rather
than asserting absence. Charge assumes conventional Lys/Arg/Asp/Glu states, not a
measured protonation assignment; histidine is omitted. Biochemical category pairs
are both charged, opposite charged, both hydrophobic and both aromatic.

Backbone polar candidates require carbonyl O–N 2.5–3.5 Å and C–O–N ≥120°, in either
direction, with non-proline donors and nonsequential residue pairs. These are
**geometry-qualified donor/acceptor candidates**, not confirmed hydrogen bonds.
M2 deliberately removes hydrogens; no H–donor–acceptor angle, protonation, binding
energy or hydrogen bond is invented from Cα proximity. Sidechain hydrogen bonds,
metal coordination and disulfides are outside this bounded feature set. Experimental
B factors, unavailable confidence and AF pLDDT retain M2's separate semantics;
none is interpreted as predictive uncertainty.

The learned message is a two-layer MLP of source state, destination state and edge
features, followed by degree-normalized aggregation and residual node update.
Hidden width 16 and two message layers yield 5,361 parameters. All richer-model
controls have identical parameters and initialization: distance-only masks backbone,
spatial and chemistry; chemistry-removed retains original connectivity flags;
chemistry-shuffled permutes whole chemical feature/mask/category vectors across
undirected edges and mirrors both directions; topology-shuffled permutes endpoint
node labels while preserving topology/degrees and breaking residue correspondence.
Zero-message suppresses aggregates while retaining the same transforms and head.
It is a node/biochemistry capacity control, not a learned geometry contribution.
The original GNN is the unchanged M3 `ResidueGNN` (3,473 parameters), rather than
M12's LayerNorm-wrapped hybrid `structure_only` model; historical M12 outputs remain
archived separately. The comparison is explicit in the preregistration.

All neural fits use CPU, four threads, seeds 0/1/2, AdamW .003, weight decay .01,
batch 32, 12 epochs and patience four. Epoch selection uses validation-only
protein-macro Spearman (primary) or native RMSE. Ridge alpha is selected from
.1/10/100 using the same validation objective. Undefined Spearman contributes zero
only to selection/macros and remains null in raw per-protein metrics. No test-driven
hyperparameter or feature search was performed.

## Independently pretrained structural encoder

The actual evaluated encoder is the official MIT-licensed
[ProteinMPNN](https://github.com/dauparas/ProteinMPNN/tree/8907e6671bfbfc92303b5f79c4b5e6ce47cdef57),
revision `8907e6671bfbfc92303b5f79c4b5e6ce47cdef57`, vanilla `v_48_020.pt`.
Config pins SHA256 of source, checkpoint and license before importing/loading them;
PyTorch loads checkpoint tensors with `weights_only=True`. All parameters are frozen.
The whole model has 1,660,485 parameters; the used feature/edge/encoder modules have
962,352. The sequence embedding and autoregressive decoder are never invoked.
There is no design/generation, fine-tuning or target-trained "pretraining."

ProteinMPNN was trained for structure-conditioned inverse folding; its
[training documentation](https://github.com/dauparas/ProteinMPNN/blob/8907e6671bfbfc92303b5f79c4b5e6ce47cdef57/training/README.md)
and [paper](https://doi.org/10.1126/science.add2187) describe a PDB snapshot dated
August 2, 2021, with crystallographic/cryoEM assemblies. Every evaluated reference
has complete mapped N/CA/C/O atoms. Encoder inference uses no coordinate noise,
full observed polymer indices and a single selected chain. It yields 128 features
per residue, before any sequence-conditioned decoding. A 585-feature ridge probe
uses mutation-site mean/sum/max encoder and substituted-residue features, global
encoder mean and count. All models keep identical cohorts; there are no extra
pretrained-encoder exclusions. Checkpoint/source binaries stay ignored in the cache.

Exact or homologous PDB exposure during pretraining has not been exhaustively
excluded. The predominantly NMR primary structures are not proof of absence of
homologs from inverse-folding pretraining. G3 is family-held-out **supervised
mutation-effect fitting**, not family-disjoint structural pretraining or unseen-fold
evaluation. The pretrained probe also differs in representation and ridge head;
its gains cannot be attributed solely to architecture.

## Reproduce

Use Python 3.12 and the measured pins in `requirements-m3.txt`:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-m3.txt
.venv/bin/python -m pip install -e '.[dev,esm,m3]'
```

Existing M6/M12 data/graph/ESM caches can be reused without fitting older milestones.
For a clean checkout, explicitly acquire their small selected sources and prepare
validated graphs (this also prepares the older ESM caches; M14 does not require an
old supervised M5 checkpoint):

```sh
.venv/bin/python -m proteinmod.family_experiments --acquire
.venv/bin/python -m proteinmod.stability_experiments download
.venv/bin/python -c 'import json; from proteinmod.embeddings import FrozenESM; FrozenESM(json.load(open("configs/m12.json"))["embedding"], local_only=False)'
.venv/bin/python -m proteinmod.family_experiments --prepare
.venv/bin/python -m proteinmod.stability_experiments prepare
```

First acquire the three small pinned ProteinMPNN files and run M14. `--prepare`
permits explicit downloads of this source/weights/license and missing M12 features;
normal runs and checks are offline. Use new output names rather than overwrite:

```sh
LOKY_MAX_CPU_COUNT=4 .venv/bin/python -m proteinmod.edge_experiments --prepare --output runs/m14-local
LOKY_MAX_CPU_COUNT=4 .venv/bin/python -m proteinmod.edge_experiments --output runs/m14-local-repeat
LOKY_MAX_CPU_COUNT=4 .venv/bin/python scripts/verify_m14.py --directory runs/m14-local --repeat runs/m14-local-repeat
MPLCONFIGDIR=/tmp/proteinmod-mpl .venv/bin/python -m proteinmod.edge_report --directory runs/m14-local
LOKY_MAX_CPU_COUNT=4 .venv/bin/pytest -q
.venv/bin/ruff check .
.venv/bin/ruff format --check .
```

The archived run uses `runs/m14-final` and `runs/m14-final-repeat`. To replay its
committed metrics exactly, retain those ignored local weights and run
`python scripts/verify_m14.py --repeat runs/m14-final-repeat`. On a clean machine,
run the commands above; do not expect binary checkpoint SHA256 or bitwise results
across different dependency versions/hardware. Every prediction, selected epoch,
trace, role, data/config/source hash and device is recorded. Repeated full CPU fits
are checked independently of disk-model replay.

The initial audit found that M13's generic manual ridge replay promoted float32
features to float64. M14 now restores the actual StandardScaler transform, preserving
fit-time dtype/rounding; its regression test compares fitted and serialized inference.
Final fits were rerun fresh with this fix. M13 and other historical source/results
are preserved; this is a local M14 inference correction, not a change in scientific
features or hyperparameters.

See [results](../benchmarks/m14/RESULTS.md),
[failure analysis](../benchmarks/m14/REPORT.md), [provenance](../benchmarks/m14/DATA_PROVENANCE.md)
and [replay checks](../benchmarks/m14/validation.json). This is M14 only; no M15/M16.

The full fresh refit used the same model code with an added checkpoint overwrite
guard (commit `6bbaa72` versus initial fitting `aad6afe`). All selected states and
predictions match exactly. The verifier checks original fit-source hashes against
that immutable Git revision and performs inference with the final implementation.
