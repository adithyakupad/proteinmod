# M15: bounded ESM-2 LoRA adaptation

The scientific comparison isolates supervised sequence adaptation before any M16
integration. New modules are `lora_model`, `lora_data` and `lora_experiments`;
existing graph, ESM, dataset and fusion APIs remain unchanged. The experiment is
[preregistered](m15_plan.md) at commit `d808fdb`, before supervised model fitting.
It is stacked on unmerged PR #28, exact verified head
`6ce820fce2b8f287b79ff92a1a576c5e761f6cf3`, with all ten CI jobs successful.

## Model and numerical contract

The existing `facebook/esm2_t12_35M_UR50D` checkpoint and tokenizer are pinned at
revision `6fbf070e65b0b7291e7bbcd451118c216cff79d8`. `configs/m15.json` additionally
binds SHA256 of safetensors, config, vocabulary and tokenizer metadata. The main
weights SHA256 is `e35647818e0e064351d4531ed480d225a002567b4b2b93ad3a9246d753150fc0`.
No checkpoint is downloaded or selected based on test results.

LoRA replaces only the final block's query/value projections:
`encoder.layer.11.attention.self.query` and `.value`. The forward is
`W(x) + B(A(x)) * alpha/r`, with rank **2**, alpha **4**, dropout **0**, random A,
zero B. Original weights, biases, embeddings, layer norms and all other projections
remain frozen. Original transformer dropout stays in evaluation mode even while
adapter gradients are enabled. There is no all-layer or full-weight fine-tuning.
The implementation uses two small PyTorch low-rank layers, following
[Hu et al.](https://arxiv.org/abs/2106.09685), avoiding a new dependency for this
fixed adaptation contract. Official [PEFT documentation](https://huggingface.co/docs/peft/package_reference/lora)
describes the same rank/scaling/target-projection conventions.

The first eleven frozen blocks are cached once per unlabelled reference/variant
sequence. Prefix identity includes immutable checkpoint/tokenizer hashes, encoder
settings, sequence content and ordered IDs, block boundary and extraction source.
Every residue token is checked against its amino acid; BOS/EOS/padding are excluded
from readout, and sequence limits cause errors rather than truncation. Prefix+tail
matches the full original ESM forward exactly for all 776 sequences (768 mutants
and eight WT references). Its frozen mutation-site features also match the existing
M12 frozen cache exactly. This is computational reuse of unchanged layers, not a
surrogate encoder. No adapter-dependent hidden state is cached across fits.

Both mutant and WT prefix states pass through the **current adapted final block**.
Gradients flow through both sides of the mutant-minus-WT difference. Site readout
is symmetric mean mutant embedding, mean mutant-minus-WT embedding and mutation
count, yielding 961 features. Mutation sets are validated against the actual
sequence. Multiple mutations retain joint contextual encoding, with order-invariant
aggregation; sequence residue order itself is preserved.

All three learned sequence models share non-affine LayerNorm, Linear(961,16), ReLU,
Linear(16,1), **15,409 trainable head parameters**, initialized identically per seed.
Frozen-head trains only this head. LoRA adds **3,840** adapter parameters, total
**19,249**. The matched-head control adds exactly the same 3,840 parameters using
two rank-2 residual 480→2→480 branches on frozen mutant-site/delta features.
Initial predictions are identical across these three models; extra capacity has
not been confounded with a different initial prediction head. Matching nominal
parameter count does not make their effective function classes or optimization
geometry identical. The frozen ESM ridge provides a stronger regularized comparator.

## Data and experimental roles

M15 uses unchanged M12 ProteinGym/Tsuboyama assay-specific stability mutation-effect
scores: 768 variants, eight domains, four externally supported Pfam families, 438
single and 330 double mutations. The task is stability-effect **ranking**, not new
functional measurement or native kcal/mol regression. No DMS-to-ΔΔG conversion,
fabricated label pairing or cross-assay RMSE is used.

Original protocols are preserved: G1 512/128/128, G2 576/96/96 per fold,
G3 384/192/192 (train/validation/test). G2 holds out proteins; G3 excludes the full
test and validation families from supervised training. In the **25% low-label**
regime, a fixed label-blind hash takes 16 original training variants per protein
in G1, 24 in G2/G3. Unselected training rows remain unused; none moves to validation
or test. All validation/test variants and structural eligibility remain unchanged.
The same nested subsets are used by every model and seed. Four families are the
effective family-level sample size, not the number of variants or seed repeats.

All fits start fresh. Only training labels determine per-assay empirical midrank
targets, ridge normalization and parameter gradients. Validation determines ridge
alpha and neural LR/epoch. Test labels never select models. Undefined protein correlations contribute zero
only to selection/macros and remain null in raw per-protein records. Supervised adapters
never see held-out protein/family labels. Extracting frozen prefix states from
held-out sequences uses no labels or trainable adaptation and is explicitly recorded.
Unknown exact/homologous ESM pretraining exposure prevents a claim of family-disjoint
pretraining, unseen-fold or broad functional generalization.

AdamW uses a fixed validation grid of head LR .001/.003, adapter/control LR one
tenth head LR, decay .01, batch32, max6 epochs, patience3, seeds0/1/2. Rank/alpha/dropout
are fixed at the single preregistered choice, not searched after inspecting results.
Training and inference use deterministic float32 CPU operations, four threads.
The label-free timing probe measured ~.0315 s/step at batch16, making CPU practical
without MPS numerical uncertainty. No MPS speed advantage is claimed.

Structural ridge, unchanged M3 GNN and M14 edge-aware GNN are refit on every exact
role/subset. Their original 12-epoch M14 settings are retained; they are scientific
baselines, not parameter- or epoch-matched LoRA controls. Structure remains validated
WT geometry with existing confidence semantics. No new fusion or cross-attention
architecture was introduced. The verifier additionally bypasses the prefix cache for selected real G3 adapters
on all eight proteins, checking a full raw-sequence forward against adapted cached
inference. All candidate traces and train/validation gaps are
retained; a short fixed budget is not a performance ceiling.

## Reproduce

Use the measured Python 3.12 pins and existing extras:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-m3.txt
.venv/bin/python -m pip install -e '.[dev,esm,m3]'
```

For a clean cache, acquire only M12's selected files, existing ESM checkpoint and
validated M2 graphs; no full ProteinGym download or previous supervised checkpoint
is needed:

```sh
.venv/bin/python -m proteinmod.family_experiments --acquire
.venv/bin/python -c 'import json; from proteinmod.embeddings import FrozenESM; FrozenESM(json.load(open("configs/m12.json"))["embedding"], local_only=False)'
.venv/bin/python -m proteinmod.family_experiments --prepare
```

The M15 runner refuses nonempty outputs/checkpoint caches. Use new direct children
of `runs/`, with unique names. `--prepare` permits extraction of missing label-free
prefix caches; it does not download or update a PLM. Normal runs and all tests are
offline once explicit acquisition is complete:

```sh
LOKY_MAX_CPU_COUNT=4 .venv/bin/python -m proteinmod.lora_experiments --prepare --output runs/m15-local
LOKY_MAX_CPU_COUNT=4 .venv/bin/python -m proteinmod.lora_experiments --output runs/m15-local-repeat
LOKY_MAX_CPU_COUNT=4 .venv/bin/python scripts/verify_m15.py --directory runs/m15-local --repeat runs/m15-local-repeat
MPLCONFIGDIR=/tmp/proteinmod-mpl .venv/bin/python scripts/report_m15.py --directory runs/m15-local
LOKY_MAX_CPU_COUNT=4 .venv/bin/pytest -q
.venv/bin/ruff check .
.venv/bin/ruff format --check .
```

Archived verification uses `benchmarks/m15` plus locally retained ignored adapter
and baseline checkpoint paths. A clean machine should refit using the commands
above. Source, checkpoint and dataset hashes, selected states, all candidate traces,
versions, device, runtime and peak process RSS are recorded. Prefix arrays, raw
coordinates, PLM and binary adapters are not committed. Exact CPU repetition is a
local check; byte identity across different hardware/software is not guaranteed.

See [numeric results](../benchmarks/m15/RESULTS.md),
[scientific failure analysis](../benchmarks/m15/REPORT.md),
[provenance](../benchmarks/m15/DATA_PROVENANCE.md) and
[reproducibility](../benchmarks/m15/validation.json). M16 has not been started.
