## Interpretation and scope

The original M16 strict 1e-6 device-parity failure remains archived and failed.
M16.1 separates deterministic same-device replay, a float32 activation screen, and
practical prediction/metric equivalence. The [policy](PORTABILITY_PLAN.md) was
committed at `b805f1c` before any new experiment. Configuration moved unchanged
from `m16.1.json` to `m161.json` because M10/M11 inventory parsers require an
integer milestone name; the first failed bookkeeping attempts are retained.
No scientific configuration, dataset split or historical source module changed.

All weights and tokens are identical. In eval mode, every transformer layer is
compared on WT plus seven variants selected without labels. The first layer where
drift appears and its subsequent propagation distinguish backend arithmetic from
stochastic training or changed inputs. Backend reduction/order differences are a
supported explanation, not proof that one particular Metal operation is responsible.
[PyTorch numerical accuracy](https://docs.pytorch.org/docs/2.14/notes/numerical_accuracy.html)
and [reproducibility](https://docs.pytorch.org/docs/2.14/notes/randomness.html)
do not promise bitwise CPU/GPU equality. The engineering activation allowance is
not a theorem; the practical metric margins are not experimentally measured noise.
No tolerance is enlarged after observing the fresh results. No test-set tuning occurs.

## Measured portability results

The empty-cache paired run took **372.781 s** on macOS 26.5.2 arm64,
PyTorch 2.14.1, float32, four CPU threads. Feature extraction alone took
175.568 s CPU and 152.570 s MPS; these are single measurements, not a hardware
speed benchmark. Original splits stayed 2,403/601/702 and all 3,706 variants were
processed. Both 65-sequence same-device repeat probes were bitwise exact.

| Representation | Maximum feature difference | CPU rho | MPS rho | Maximum prediction change / training SD |
|---|---:|---:|---:|---:|
| Mean | 5.24521e-6 | 0.4983552 | 0.4983788 | 6.41497e-5 |
| Delta | 3.81470e-6 | 0.4983552 | 0.4983788 | 6.41418e-5 |
| Mutation sites | 2.90275e-5 | 0.6340530 | 0.6340508 | 3.79827e-5 |

All three pooled feature screens pass; their maximum error/budget ratios are
0.02149, 0.08250 and 0.42063. All functional comparisons pass the preregistered
0.001 margins with identical validation-selected alphas and valid fixed-weight
linear propagation bounds. Maximum refitted prediction discrepancy is 3.62634e-6;
the original absolute 1e-6 criterion **still fails**. Site RMSE is 0.0399555059 CPU
versus 0.0399555521 MPS. M0 classical predictions remain exactly historical.
The 1% deliberately corrupted activation control fails by 108.68 times its budget.

**Intermediate residual activations do not all pass.** Differences appear in the
first transformer layer (max 2.38419e-5), grow through nonlinear/residual operations,
and reach 2.82288e-4 before the final encoder normalization. Raw layers 11 and 12
have maximum error/budget ratios 1.01308 and 2.13738; the preceding ten pass.
The fixed depth-based screen is therefore insufficient as a universal intermediate
activation guarantee. This failure is preserved, not reinterpreted as a pass or used
to choose another tolerance. Final normalized/pooled features and downstream function
metrics pass only on the tested platform/cohort. No individual Metal kernel has been
isolated as the sole cause, and no CUDA or other Apple hardware is qualified.

The complete numerical records, per-device held-out predictions, learning curves,
and original cohort IDs are in [the evidence](../benchmarks/m161/). Full curves use
all six original fractions and three nested subset seeds on each device; they are
retained for inspection, not treated as extra independent test sets. Practical
full-data equivalence is the declared primary portability endpoint; low-label
rank ties can be sensitive and no universal low-label equality is claimed.

## Safe stability inference

Use the guarded public interface:

```sh
python -m proteinmod.stability_inference --output runs/safe-stability.json
# after editable installation, equivalently:
proteinmod-stability --output runs/safe-stability.json
```

It verifies the immutable M8 input SHA and exclusively creates a separate JSON
export. All 13,848 function-domain predictions have `prediction: null`, `unit: null`,
`thermodynamic_eligible: false`, with a reason. Both ESM and structural predictions
are excluded; plausible magnitude does not establish thermodynamic validity.
Neither caller-supplied domain flags nor clipping can enable physical output.
Raw historical CSV values are left intact for diagnostic replay. The old experiment
commands remain research/diagnostic paths, **not a deployment API**. They can still
reproduce invalid raw values; consumers must not present those as physical ΔΔG.
The extreme structural offsets remain an observed failure, not repaired predictions.

The new interface fails closed for every source until a separate native model,
reference, assay, condition, units/sign and qualification contract is implemented.
M6's held-out native results are valid bounded experimental evaluations, not a
license to extrapolate them to M8 function proteins. Native labels remain kcal/mol,
positive destabilization, with the original source sign conversion. No fabricated
paired labels or a universal stability predictor are introduced.

## Reproduction

Use the environment in the evidence requirements file and the pinned M3 requirements.
From the repository root with **absent** `data/cache/m16.1` and `runs/m16.1`:

```sh
python -m pip install -r requirements-m3.txt -e '.[dev,esm,m3,structure]'
HF_HUB_DISABLE_XET=1 LOKY_MAX_CPU_COUNT=4 MPLCONFIGDIR=/tmp/proteinmod-m161-mpl \
  python scripts/reproduce_m16_1.py
python scripts/cold_sources_m16_1.py
python -m proteinmod.stability_inference --output runs/m16.1/safe-stability.json
python scripts/license_inventory_m16_1.py
ruff check .
ruff format --check .
pytest -q
python -m pip check
python scripts/audit_m16.py
python scripts/verify_m16_1.py
```

The paired run deliberately requires native MPS; CPU-only CI verifies archived
results and synthetic rejection tests. Cold acquisition uses public URLs without
ambient Hugging Face credentials, pinned revision/file hashes, no old feature/model
cache, and original train/validation/test IDs. It generates full original M1 probes
and 18 seeded training-fraction evaluations per model per device, not just one fit.
M0 is independently fitted inside both M1 comparison runs and checked against its
historical predictions. Caches, raw weights/archives and large arrays are not committed.
A failed/incomplete cold attempt is preserved; choose a fresh configured path rather
than silently resuming or overwriting it. Network-host changes can fail pinned checks.

The structure run separately redownloads 1UBQ PDB and mmCIF, reconstructs mapping,
contacts and solvent accessibility, and compares format outputs. Its mutations are
synthetic mapping probes, not new measured labels. The M6 source run redownloads
both primary archives and reconstructs 1,800 native singles with original sign,
reference mapping and exclusion audits; it does not retrain the transfer encoder.

Historical checkpoint replay follows `scripts/qualify_m16.py replay` in a fresh
checkout with the documented caches. The first active replay snapshot was interrupted
by the configuration rename; corrected M10–M15 invocations and their logs are retained.
The first source audit also encountered the staged rename and then an unfinished
document link; those pre-final attempts do not constitute scientific failures.
The final audit is rerun after files and documentation are complete.
M12–M15 verifiers receive copied evidence directories so archives are never rewritten.
See the original [M16 reconstruction instructions](M16.md#reproduction) for full fits.

## Feature and supported-inference matrix

| Research path | Trained/evaluated scope | Supported interpretation | Universal integration |
|---|---|---|---|
| M0/M1 sequence ridge | Amylase official variants | Assay-unit effect on verified substitutions | Independent models |
| M3 structural ridge/GNN | Matched amylase structure sites | Reference-geometry function effect | No general protein guarantee |
| M4/M5 ESM–GNN attention | Three function proteins, G1/G2 | Train-assay rank function effect | Sequence + graph + attention integrated |
| M6 native stability | Three exact small constructs / held-out proteins | Native ΔΔG evaluation, kcal/mol, positive destabilization | Separate continuous head; domain-specific |
| M7 independent/joint | Unpaired function/native stability | Separate masked task heads; measured negative transfer | Shared representation evaluated; no universal checkpoint |
| M8 stability conditioning | Function G1/G2 | Historical diagnostic; thermodynamic inference blocked | Invalid OOD scalars not physical inputs |
| M9 assay metadata | Crossed protein/endpoint cohort | Assay-aware rank effect | Metadata unknown/missingness explicit |
| M10 reliability | M9 matched structures | Typed pLDDT/B-factor inputs and learned gate | Structure confidence is not predictive uncertainty |
| M11 interactions | GB1 measured combinatorial variants | Symmetric mutation interactions | No universal multi-protein epistasis claim |
| M12–M14 families/uncertainty/edges | Eight domains/four Pfam families, G1/G2/G3 | Ranking; model/cohort-specific intervals with eligibility | Separate graph/ensemble/attention states |
| M15 LoRA | Same family cohort; last-layer q/v rank-2 adapters | Benchmark rank predictions, including known single/multiple variants | Bounded inference script; no thermodynamic units |

The existing single/multiple inference example verifies known benchmark substitutions
and checkpoint identity, not arbitrary unseen proteins. B-factors are experimental
atomic displacement measures; pLDDT is predicted local structure confidence; ensemble
spread/conformal intervals describe predictive uncertainty under their own assumptions.
None establishes calibrated unseen-family uncertainty automatically. No single trained
checkpoint simultaneously integrates all these extensions. Negative results and
pretraining-overlap uncertainty remain in the original milestone reports.
